## Slash commands

Type `/command` directly in the Claude Code prompt. Each command is a skill in
`.claude/skills/<command>/SKILL.md`. Skills that change git state or decisions run
only when you type them; the rest Claude may also start on a matching request.

| Command | What happens |
| --- | --- |
| `/organize` | Switch to Organizer mode – discuss workflows, edit skills and rules |
| `/architect` | Switch to Architect mode – discuss architecture → write `.context/plan.md` |
| `/next` | Architect mode: suggest first incomplete item from `.context/to-do.md` |
| `/dev` | Switch to Developer mode – read `.context/plan.md`, create branch, write code |
| `/go` | After the discussion: plan, code, polish, verify, commit, close – without stops |
| `/polish` | Clean up generated code – built-in `simplify` + project rules from `.claude/rules/` |
| `/record` | Add ADR to `.context/decisions.md` |
| `/commit` | Show diff → wait for confirmation → commit |
| `/close` | Rebase + ff-merge into `dev`, delete branch |
| `/report` | Archive old `status.md`, write new one |
| `/sync` | Compare code with documentation, suggest changes |
| `/summary` | After a task or release: report, sync, commit, close – without stops |
| `/retro` | Analyze project history → write discussion → propose to-do and ADR updates |

## Branches

```text
main          ← releases (dev → main manually)
  └── dev     ← integration
        └── feature/<name>   ← all work goes here
        └── hotfix/<name>    ← urgent fixes → main
```

CC **never does `git push`** without explicit request.

## Typical workday

```text
0. Session start – CC reads automatically:
   .context/blueprint.md → .context/to-do.md → .context/status.md

1. Pick a task
   → /next
   CC reads to-do.md, suggests first incomplete item

2. Discuss
   → /architect
   CC asks questions, records decisions.
   Before writing .context/plan.md, CC asks about feature branch (plan.md is task-local, ADR-030).
   To record an architecture decision: /record

2a. Shortcut – everything is discussed
   → /go
   CC runs steps 3–5 without stops: plan.md, code, /polish, verification, commits,
   /close. It stops only for your steps (push, release), a conflict with an ADR or a
   check it cannot fix. Decisions it took on its own are listed in the report under
   "Decided without you".

3. Implement
   → /dev
   Already on feature branch (from step 2). CC reads plan.md, writes code + tests.
   If invoked without a feature branch, /dev will create one.

4. During work – commits
   → /commit
   CC shows what will be included, waits for confirmation, commits

4a. Before final commit – polish (optional)
   → /polish
   CC runs built-in simplify + project rules on the diff
   Presents findings per item: apply / skip / discuss
   Args: /polish <path> | /polish --staged | /polish (whole feature diff)

5. Task done
   → /close
   CC does rebase + ff-merge into dev, deletes branch

6. Every few tasks – sync documentation
   → /report  (update status.md)
   → /sync    (check blueprint / code divergence)

6a. Shortcut – after a task or a release
   → /summary
   CC runs /report, /sync with every recommended edit applied, commits and /close –
   without stops. Edits it applied on its own are listed under "Decided without
   you", questions for the architect – in the report.

7. Periodically – retrospective
   → /retro
   CC reads decisions, history, git log – presents analysis draft
   You correct → CC writes .context/history/retros/YYYY-MM-DD.md
   Proposes to-do and ADR updates with per-item confirmation
```

## Commits

Format: `type: description`

| Type | When |
| --- | --- |
| `feat:` | new functional code |
| `fix:` | bug fix |
| `docs:` | documentation only |
| `refactor:` | refactoring without behavior change |
| `test:` | tests |
| `chore:` | infrastructure, configuration, dependencies |
