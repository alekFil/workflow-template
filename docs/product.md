# workflow-template – product

Что такое шаблон и зачем он нужен. Как он устроен – `.context/blueprint.md`.
Файл правит только владелец; агент предлагает правки.

## Назначение

Шаблон рабочего процесса для разработки с Claude Code. Он ставится в git-репозиторий
одной командой и дает агенту структуру: описание продукта, решения, задачи, скиллы
режимов и правила текста.

## Пользователи

- Разработчик, который работает с Claude Code один.
- Небольшая команда, где каждый работает со своим Claude Code в общем репозитории.
- Разработчик, который вносит вклад в чужой OSS-проект и держит свой контекст
  приватно.

## Принципы

- Контекст агента – файлы в git, а не память чата.
- Общий текст не порождает конфликтов слияния: один файл на сущность, индексы
  генерируются.
- Агент предлагает, владелец решает: ADR, описание продукта и `CLAUDE.md` меняются
  только с согласия владельца.
- Скилл завершается в своих границах и не запускает соседний скилл сам.
- Установка не трогает чужие файлы: `.gitignore` дописывается, а не заменяется.

## Ключевая функциональность

- Установка через `curl` с выбором ветки, тега или локального клона.
- Скиллы режимов: `/architect`, `/dev`, `/go`, `/close`, `/summary` и другие.
- Профили: обычный проект, devmeta для своего OSS, devmeta для вклада в чужой.

## Non-goals

- Поддержка агентов кроме Claude Code (Codex, OpenCode): скиллы писались бы по
  наименьшему общему знаменателю, а проверить совместимость некому.
- Генерация кода проекта под стек (Cookiecutter и подобное).
- Трекер задач вместо GitHub Issues: карточки задач – контекст агента, а не
  публичный бэклог.

## Граница продукта

Шаблон задает процесс работы с агентом и структуру его контекста. Код, стек и
инфраструктура проекта остаются за пределами шаблона.
