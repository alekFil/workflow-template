# Профили devmeta: приватный контекст для своего OSS и для вклада в чужой

## Контекст

Нужно вносить вклад в чужой OSS-проект с этим workflow так, чтобы контекст агента
оставался у владельца, версионировался и не попадал в форк. Та же модель нужна для
своих OSS-проектов: публичная история кода, приватные рассуждения.

## Решение

1. Три профиля в `.claude/workflow.conf` (`PROFILE`), выбор при установке:
   `project`, `own-oss`, `contribution`.
2. Devmeta: корень – приватный репозиторий с `CLAUDE.md`, `.claude/`, `.context/`,
   `docs/`. Код клонируется в `code/`, которую devmeta игнорирует. Claude Code
   запускается в корне и штатно видит контекст; `CLAUDE.md` проекта в `code/`
   подгружается сам.
3. Защита устройством каталогов, а не дисциплиной: `workflow.sh bootstrap` ставит в
   `code/.git/hooks/pre-commit` локальный хук, который не пускает `CLAUDE.md`,
   `.claude/`, `.context/` в код. Хук не коммитится и не уходит в upstream.
4. Скиллы работают с двумя репозиториями: код – `git -C code`, контекст – корень.
   Коммиты в `code/` не несут trailers workflow; `/close` записывает коммиты кода в
   коммит devmeta с `Closes-Task`.
5. В devmeta одна ветка `main`. Ветки задач есть только в `code/`.
6. `own-oss`: ADR публичные в `code/docs/decisions`, `docs/product.md` приватный.
7. `contribution`: `BRANCH_MODEL=trunk`, `MERGE_MODE=pr`, pull request в
   `UPSTREAM_REPO`; ADR и product file не ведутся; правила upstream важнее наших.
8. Новая машина: клонировать devmeta и запустить `workflow.sh bootstrap`.

## Альтернативы

- **Контекст внутри форка, скрытый через `.git/info/exclude`.** Не версионируется,
  конфликтует со своим `CLAUDE.md` upstream, одна команда `git add -f` отправляет
  контекст в pull request.
- **Соседний репозиторий и `--add-dir`.** `CLAUDE.md` из дополнительной папки
  требует отдельной настройки; Claude Code запускается в коде, и контекст вторичен.
- **Название подпапки `app/`, `upstream/`, `external/`, `oss/`.** Не подходит для
  библиотеки, путается с remote `upstream`, неверно для своего проекта или
  привязано к открытости. `code/` нейтрально.

## Последствия

- Хук блокирует и правку собственного `CLAUDE.md` upstream; намеренная правка –
  `WT_ALLOW_WORKFLOW_FILES=1 git commit`.
- Опция «скрыть файлы ассистента» нужна только профилю `project`.
