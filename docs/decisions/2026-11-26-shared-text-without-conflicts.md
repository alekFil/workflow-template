# Общий текст без конфликтов: ADR по файлам, карточки задач, status вне git

## Контекст

Цель шаблона – командная работа без конфликтов в сгенерированной прозе. Конфликты
давали общие файлы, которые правит каждая ветка:

- `decisions.md`: агенты на разных ветках создавали ADR с одним номером, а запись в
  один файл конфликтовала. ADR создавали `/go`, `/summary`, `/sync`, `/architect`,
  хотя ADR – важнейшие решения проекта, а не все подряд.
- `to-do.md`: 37 выполненных пунктов из 47, файл правили `/report`, `/summary`,
  `/sync`, `/retro`.
- `status.md`: `/report` переписывал его целиком на каждой ветке.

ADR раньше лежали в `docs/` и переехали в `.context/` (бывший ADR-006): папку
`.context/` объявили служебной. Но ADR – знание о проекте для людей, а не рабочее
состояние агента.

## Решение

1. Три класса общего текста (`.claude/rules/artifacts.md`): коллекции сущностей –
   один файл на сущность и генерируемый индекс; производное состояние – только
   генерируется; курируемые одиночки – правятся по согласию владельца.
2. ADR – в `docs/decisions/YYYY-MM-DD-<slug>.md` с frontmatter (`title`, `status`,
   `date`, `superseded-by`). Индекс `docs/decisions/README.md` генерирует
   `.claude/scripts/workflow.sh adr-index`. Замененный ADR остается на месте со
   статусом; архив `history/decisions/` удален.
3. ADR создает только владелец через `/record`. Остальные скиллы перечисляют
   кандидатов в ADR в карточке задачи или в отчете.
4. Задачи – карточки `.context/tasks/<slug>.md` со статусом `next`, `in-progress`,
   `rejected`. План – раздел `## Plan` карточки вместо `.context/plan.md`. `/close`
   удаляет карточку коммитом с trailer `Closes-Task: <slug>`; коммиты реализации
   несут `Task: <slug>`. Список выполненного строится из git
   (`workflow.sh done`), файла с ним нет.
5. Отклоненная карточка остается со статусом `rejected` и причиной: в git ее нет, а
   без нее агент предложит идею снова.
6. `.context/status.md` не коммитится: `/report` генерирует его по запросу.
7. Пути и профиль – в `.claude/workflow.conf`, его читают скиллы и скрипт.
8. Мейнтейнерский слой мигрирован: 28 ADR разнесены по файлам с `legacy-id`,
   `to-do.md` превращен в карточки.

## Альтернативы

- **Номера ADR, присвоенные при слиянии.** Привычные номера, но ссылки внутри ветки
  пришлось бы переписывать при слиянии.
- **Индекс ADR, который правят руками.** Конфликты переехали бы в индекс.
- **`history/done.md` для выполненных задач.** Один файл, куда дописывают ветки,
  снова дает конфликт в конце файла; историю уже несут git и ADR.
- **`status.md` генерировать только в основной ветке.** Сложнее, а файл все равно
  производный.

## Последствия

- Заменяет `2026-08-30-adr-discipline` (нумерация и архивация),
  `2026-08-30-status-without-file-archive`, `2026-08-31-plan-task-local` и
  `2026-08-31-commit-plan-after-architect`: план теперь едет в ветке как часть
  карточки.
- В `2026-08-31-notes-discussions-retros` больше нет `history/decisions/`, остальное
  в силе.
- Развернутым проектам нужна миграция (карточка `migrate-deployed-projects`).
