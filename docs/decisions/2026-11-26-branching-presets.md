# Модель ветвления и режим слияния выбираются при установке

## Контекст

Шаблон знал одну модель: `main` / `dev` / `feature/*` / `hotfix/*` с локальным
ff-only слиянием. Обоснования этой модели нигде не было – она жила только в
`CLAUDE.md`. Для работы одному с агентом `dev` и `hotfix/*` лишние. Для команды
мешает другое: `/close` сливал ветку локально, без push и pull request.

Установщик спрашивал «Create dev branch?», но `/close` всегда сливал `feature/*` в
`dev`. При ответе «нет» `/close` сливал ветку в несуществующую ветку.

## Решение

Две независимые настройки в `.claude/workflow.conf`, их задает установщик:

| | `MERGE_MODE=local` | `MERGE_MODE=pr` |
| --- | --- | --- |
| `BRANCH_MODEL=trunk` | trunk solo | GitHub flow |
| `BRANCH_MODEL=dev` | прежняя модель | git flow для команды |

- Правило `.claude/rules/branching.md` описывает обе модели и оба режима; скиллы
  берут целевую ветку и способ слияния из настроек, а не перебирают варианты.
- В режиме `pr` выбор режима при установке – постоянное разрешение владельца
  пушить ветки задач. `main`, `dev` и теги по-прежнему пушит только владелец.
- В модели `dev` установщик сам создает `dev` после первого коммита.
- По умолчанию в установщике: `trunk` и `local`. Мейнтейнерский слой этого репо
  остается на `dev` и `local`: `dev` – канал разработки, `main` – стабильная версия.

## Альтернативы

- **Чистый trunk без веток задач.** Ломает карточку задачи как task-local артефакт
  и ревью плана вместе с кодом.
- **Комплект скиллов на каждый вариант.** Четыре копии каждого скилла, который
  работает с ветками.
- **Оставить одну модель.** Шаблон не подходит ни для работы одному (лишние ветки),
  ни для команды (нет pull request).

## Последствия

- Вопрос «Create dev branch?» из `2026-06-20-assistant-lifecycle` заменен выбором
  модели; удаление ассистента из того решения в силе.
- Каждую правку скиллов, работающих с ветками, проверять для четырех сочетаний.
