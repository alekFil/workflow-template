# Команда `/go` – вся задача без остановок

**Контекст:** ADR-031 запрещает команде исполнять соседнюю команду автоматически. Цепочка
`/architect` → `/dev` → `/polish` → `/commit` → `/close` поэтому требует от владельца
пять вызовов и подтверждения внутри `/polish` и `/commit`. В рабочих проектах владелец
принимает решения в обсуждении, а потом ждет готовый результат. Каждая остановка после
обсуждения – это ожидание без новых вопросов. Команда появилась в проекте
iteach-academy и перенесена в шаблон.

**Решение:**

1. **Отдельная команда `/go` в обоих слоях.** Вызов `/go` – явное разрешение владельца
   пройти всю цепочку за один запуск: ветка, `plan.md`, реализация, `/polish`,
   проверки, коммиты, `/close`. Альтернатива «ослабить ADR-031 для всех команд»
   убирает защиту там, где владелец хочет видеть каждый шаг. Альтернатива «флаг
   `--auto` у `/dev`» прячет выход за границы `/dev` в аргумент. Отдельная команда
   оставляет ADR-031 в силе и делает исключение видимым в таблице команд.
2. **Правило развилок вместо вопросов.** Развилку, которую обсуждение не закрыло,
   CC решает сам: берет вариант, который рекомендовал бы. Решение записывается в
   `### Changes along the way` и в отчет, раздел «Решил без вас». Владелец проверяет
   его после, а не во время работы.
3. **Жесткие остановки остаются.** `/go` не снимает остановку на шагах владельца
   (`git push`, слияние `dev` → `main`, теги), на конфликте с принятым ADR, на
   проверке, которую нельзя исправить в задаче, и на конфликте rebase. Тест или
   проверку нельзя отключать или ослаблять, чтобы пройти дальше. Проект дописывает
   свои остановки: сервер, продакшен, данные заказчика.

**Последствия:**

- Раздел «Skill boundaries» в `CLAUDE.md` обоих слоев получает исключение для `/go`.
  ADR-031 действует для остальных команд.
- `template/WORKFLOW.md` получает шаг 2a: `/go` после обсуждения.
- Цена: владелец видит результат целиком, а не по шагам. Ошибочное решение по
  развилке попадает в `dev` и исправляется новой задачей.
