# Режим `/polish --all` – полный прогон по проекту без `simplify`

**Контекст:** ADR-023 п. 7 оставил кейс «вся ветка перед `/close`» отложенным. На практике возникает потребность прогнать `/polish` по всему коду проекта (не по diff): работа ведется напрямую на `dev` без feature-ветки, готовится крупный релиз, накопились изменения от ручных правок вне обычного цикла `/dev`. Дефолтный diff-режим `/polish` (`merge-base HEAD dev..HEAD`) для этого не подходит – он ограничен точкой ветвления.

**Решение:**

1. **Аргумент `--all`** – новый режим `/polish`. Scope: все tracked-файлы (`git ls-files`), с необязательным исключением через `.polishignore` (формат совпадает с `.gitignore`). Файл не создается по умолчанию ни в мейнтейнерском, ни в шаблонном слое.
2. **В режиме `--all` встроенный `simplify` не вызывается.** Работают только project-rules из `.claude/skills/project/rules/*.md`. Причина: `simplify` рассчитан на diff, полнопроектный прогон даст шум и рискует превысить контекст. Это тот же fallback-режим «rules only», который уже описан в ADR-023 п. 2.
3. **Confirm перед запуском.** Показать количество файлов и приблизительный объем. Защита от случайного тяжелого прогона.
4. **Пункт 3 ADR-023 (аргументы команды) расширяется** строкой `/polish --all` – «полный прогон по всем tracked-файлам, только project-rules».

**Последствия:**

- `cc-code-polish.md` в обоих слоях получает новую ветку алгоритма и confirm-шаг.
- Появляется опциональный `.polishignore` – контракт совпадает с `.gitignore`, отдельно не документируется.
- В шаблонном слое `.polishignore` по умолчанию не создается – пользователь заводит его сам при необходимости.
- Мейнтейнерский слой получает 2 живых правила – `markdown-conventions.md` и `no-placeholder-leaks.md`. Впервые задействуется точка расширения из ADR-023.
- **П.5 отменен ADR-025** – правило bold-as-heading исключено из `markdown-conventions.md`; остальные пункты правила актуальны.
- Если позже потребуется полнопроектный прогон с `simplify` – отдельный ADR.
