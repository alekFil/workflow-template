# Команда `/summary` – итог задачи или релиза без остановок

**Контекст:** После задачи или релиза владелец запускает `/report`, `/sync`,
`/commit` и `/close` по очереди. `/sync` по ADR-031 останавливается и ждет согласия
на каждое предложение, `/commit` – подтверждения. На практике владелец принимает
почти все рекомендованные правки, и цепочка из четырех вызовов – это ожидание без
новых решений. Команда появилась в проекте iteach-academy и перенесена в шаблон.

**Решение:**

1. **Отдельная команда `/summary` в обоих слоях**, по образцу `/go` (ADR-034).
   Альтернатива «флаг `--apply` у `/sync`» закрывает только один шаг из четырех.
   Альтернатива «встроить отчет в `/go`» смешивает задачу и итог: синхронизация
   документации нужна раз в несколько задач, а не после каждой.
2. **Рекомендованные правки `/sync` применяются без согласия.** Это главное отличие
   от ручной цепочки. Каждая такая правка попадает в отчет, раздел «Решил без вас».
   Новый ADR пишется, только если проходит чек-лист `/record`; вопросы архитектору
   из `status.md` CC не решает сам, а выносит в отчет.
3. **Запуск только с `main` или `dev`.** На `feature/*` команда останавливается:
   отчет о незакрытой ветке описывал бы состояние, которого нет в истории.
4. **Жесткие остановки как у `/go`**, плюс одна своя: расхождение, которое требует
   правки кода или границ проекта, а не документации, не «чинится» в документах.

**Последствия:**

- Раздел «Skill boundaries» в `CLAUDE.md` обоих слоев получает исключение для
  `/summary`; ADR-031 действует для остальных команд.
- `template/WORKFLOW.md` получает шаг 6a: `/summary` после задачи или релиза.
- Цена: правка документации, с которой владелец не согласен, попадает в `dev` и
  откатывается новым коммитом. Отчет перечисляет все такие правки.
